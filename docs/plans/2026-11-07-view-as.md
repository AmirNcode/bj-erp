# View As Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The single admin opens the app as any active employee, strictly read-only, to check what that person can see, and exits back to their own view.

**Architecture:** A short-lived row in `private.view_as_sessions`, named by an httpOnly cookie. The app sends the ID as `x-view-as`, and a PostgREST pre-request hook swaps `sub` in `request.jwt.claims` and sets the transaction read-only, so all RLS and RPCs treat the request as the target. The header follows the cookie, so a dead view fails closed. Each render proves the swap with a probe.

**Tech Stack:** Next.js App Router, TypeScript, PostgREST v12.2.3, Postgres, GoTrue, next-intl, Vitest with testing-library, Playwright, psql SQL tests, bash deploy tests.

**Spec:** `docs/specs/2026-11-07-view-as-design.md`

## Global Constraints

- Branch from `origin/main` (`3ac4002`) as `claude/view-as`. Uncommitted docs carry over. Leave the `AGENTS.md` change alone and out of every commit.
- Commit only as the plan says, once the owner has approved execution. No push and no PR until asked. Pushing `main` deploys to Liara. End every commit message with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.
- Verify library APIs against Context7 before use (CLAUDE.md): next-intl, Next.js 16 route handlers and cookies, `@supabase/ssr`.
- Migrations: edit `supabase/migrations/` only. Dry-run on a clone before anything applies it (CLAUDE.md "Dry-run migrations first"). Never hand-run SQL on a server.
- Local DB holds the real roster: e2e uses `999…` users only. Never run `accrual.spec`.
- Session limit 30 minutes. Cookie `bj-view-as`, httpOnly, `secure` in production, `sameSite=lax`, `path=/`, `maxAge` 24 hours.
- Header `x-view-as`. Hook error message exactly `view-as refused`, sqlstate `PT403`.
- Audit actions `view_as.start` and `view_as.end`, `entity` = `profiles`, `entity_id` = target.
- Strings: everything on the strip is `fa` + `en`. The `admin.*` namespace is `messages/en.json` only, as today. `'use client'` components read text with `useTranslations`.
- No signing key, no `service_role`, nothing that reads `JWT_SECRET` in the app.

## Review Focus

- A target with only a custom role: nav must follow their permissions, though `app_roles` omits custom roles. (Task 6 test)
- A person with no personnel number: search result and strip must read cleanly, with no empty brackets. (Task 5 and 6 tests)
- A leftover cookie, then a different person logging in on that browser: they must reach Home, not a page of errors. (Task 7 test)
- A view that dies with a form open: pressing Save must be refused with "view ended", and the person's data must not change. (Task 7 test)
- Exit in one tab with another tab open as the person: the other tab must reload as the admin. (Task 7 test)

- The three `app_*` session functions are granted to `authenticated` only. The probe may also go to `anon`, because it reveals nothing.
